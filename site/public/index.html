One schema. A website and a phone app.

Selasih Mobile is an invented mobile operator, built in Strata to show one thing: the database, the billing rules, the web pages and the phone screen are checked together, in one build.

The screens

Produced by the Strata compiler from layout blocks, using rows from a database block and prices from one rules file. No template engine, no framework, no JavaScript.

Where the money is decided

Once, in one file, checked against the same schema:

float overage_for(int plan_id, float used) {
    list[Plan] found = Plan <- [id == plan_id];
    for p in found {
        return over_quota(used, p.monthly_quota_gb) * OVERAGE_PER_GB;
    }
    return 0.0;
}

The web page and the phone screen both call it. Neither has its own copy of the arithmetic, so neither can disagree with the bill.

Try it

git clone https://github.com/prabathkumar/strata-core
cd strata-core && bash tools/install.sh
strata new myapp && cd myapp && strata run

What it is not

Pre-release, weeks old, written by one person. No package registry, no threads, no joins, no JavaScript, and an ecosystem consisting of one repository. Selasih Mobile is invented and is not a real operator. For almost any project you would start today, C# or Java is the right answer — the README says so in a comparison table that concedes every row it should.

This page is hand-written HTML. The three screens linked above are not — they are compiler output, which is the part worth looking at. They are rebuilt on every push, so a screen that stopped compiling would stop appearing here.

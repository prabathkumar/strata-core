The compiler is the code reviewer.

Strata checks your database, your business rules and your screens as one thing. Rename a column and the build fails in the query, the total and the line of screen that showed it — before anything ships.

See it

These two pages were produced by the Strata compiler from layout blocks, using rows from a database block. No template engine, no framework.

Why that is unusual

In a typical stack the compiler checks your code against your model, and whether the model matches the database is a migration somebody hopefully ran. Strata closes that gap: schema, rules and screens are one type system, so the mismatch is a build error rather than a customer's problem.

database Order { int id; str customer; float amount; str status; }

layout OrdersBoard() {
    list[Order] open = Order <- [status == "OPEN"];
    for Row in open { text Row.customer; }   // rename `customer` → this fails
}

Try it

git clone https://github.com/prabathkumar/strata-core
cd strata-core && bash tools/install.sh
strata new myapp && cd myapp && strata run

What it is not

Pre-release, weeks old, written by one person. No package registry, no threads, no joins, and an ecosystem consisting of one repository. For almost any project you would start today, C# or Java is the right answer — the README says so in a comparison table that concedes every row it should.

This page is hand-written HTML. The two demo pages above are not — they are compiler output, which is the part worth looking at.

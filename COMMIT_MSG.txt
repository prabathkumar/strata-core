feat(layout): render layouts to HTML from the C backend

The cross-tier contract is now visible, not only enforced. A layout
compiles to a C function that writes HTML, `render X to "file"` calls it,
and declarative properties map onto inline CSS:

  <body style="width:1200px;height:800px">
    <div style="display:flex;flex-direction:row;padding:16px;background:#0c0c12">
      <span style="color:#39ff14;font-weight:bold;font-size:16px">OPERATIONS</span>

Server-rendered from the existing backend rather than through WebAssembly:
no new code generator, and the guarantee is identical either way because
the check happens in the compiler before anything is emitted. WebAssembly
remains on the roadmap for compute-heavy client work.

The dynamic section renders no rows, and says so in a comment in the
generated C. Queries evaluate to NULL because there is no database
runtime yet; the loop is emitted with a correctly typed row variable so
the body compiles, and nothing is fabricated to make the page look
populated.

A property with no CSS mapping is dropped rather than guessed at, and an
element's label is emitted as a literal, as an expression, or not at all
when it is a bare identifier naming the element.

Layouts are now registered as renderable alongside reports, so `render`
accepts either.

Also of note: `title` is a reserved word and could not be used as a local
variable here — the third time this has come up, after `model` and
`metrics` in Phase 4. Reserving report-block field names globally is a
poor trade and they should become contextual keywords.

All eight suites green, fixpoint holds, examples compile 10 of 17.

feat(runtime): in-memory tables — the cross-tier demo renders real rows

Queries evaluated to NULL, so the layout rendered nothing and the
generated C said so in a comment. Database blocks now have storage:

  database ServiceMetric { ... }   ->  static ServiceMetric* ServiceMetric__rows[...];
  ServiceMetric <- [id = 1, ...]   ->  allocates a row and appends it
  ServiceMetric <- [status == "X"] ->  filters into a NULL-terminated array
  for Row in degraded { ... }      ->  iterates it

examples/cross_tier_contract.sta now seeds three services, queries the
two that are DEGRADED, and renders them:

  <span style="color:#ffffff">auth-gateway</span>
  <span style="color:#ff4a4a">91.4</span>

Deliberately the simplest thing that makes the contract observable end to
end: fixed capacity, no persistence, no index, no transactions. The
roadmap says so rather than implying a database exists.

Inside a query condition a bare identifier naming a column resolves to
the row under test, which is what lets `[status == "DEGRADED"]` read the
way it does.

Two conversion bugs surfaced while making the demo render:

  - str() always called the integer converter, so a float was silently
    truncated: 91.4 rendered as 91. It now dispatches on the argument's
    type, which needed member access to resolve its declared field type.
  - strata_float_to_str used a fixed %.6f, so every float printed padded
    (91.400000). It now uses the shortest representation that reads back
    as the same double — %.17g always round-trips but shows binary noise
    as 91.400000000000006 — and keeps a trailing .0 so a float still
    looks like one.

Ported to both implementations in the same change; all nine suites green
and the fixpoint holds. Conformance 79.

fix(codegen): generated C relied on implicit function declarations

CI failed on a job that passed locally. The cause was not configuration:
the generated C called unresolved symbols without a declaration, which
C99 removed and clang 16+ rejects outright. gcc only warns. GitHub's
runner image has clang, stage0 prefers clang, and this machine has only
gcc — so the same source compiled here and failed there.

This was a real portability defect, not a CI problem. Any user on a clang
toolchain, which is every macOS developer, would have hit it the first
time a program referenced a symbol Strata could not resolve locally —
`current_raw_buffer` in the README's own packet example, for instance.

Unresolved externals are an accepted state: the import pass reports them
and leaves them to the linker. Codegen now passes
-Wno-implicit-function-declaration so that intent survives a strict
frontend, rather than depending on which compiler happened to be
installed.

STRATA_CC pins the backend compiler, and CI now runs the conformance and
documentation suites under clang as well as the default. Testing one
toolchain while users have another is the same class of gap as testing
documentation that is never compiled.

Verified by reproducing the failure locally with
-Werror=implicit-function-declaration, which turns gcc into clang 16 for
this diagnostic.

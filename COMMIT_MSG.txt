build: generate release notes from git history and live verification

tools/release_notes.py groups commits since the previous tag by
conventional-commit prefix and fills a verification table by running each
suite at generation time. No figure in a release is typed in by hand.

This project has twice published a claim that was false when written: a
commit announcing "32/32 passing" against a suite that was failing 30/31
with a segfault, and a "Stage 2 self-hosting complete" milestone for a
compiler that did not compile. A release note stating a number no tool
produced is the same failure in a more visible place.

A failing suite reports FAILING in its row, adds a "this build is not
green" banner, and exits non-zero, so notes for a broken build look
broken. Verified by injecting a type error into a README example and
confirming the Documentation row flipped and the exit code changed.

Two bugs in the generator, both found by checking its output against
measurements taken earlier by hand rather than trusting it:

  - The native-C line counter closed a block only on a line ENDING with
    the terminator, so a one-line `int f() { native "..."; }` never
    closed and every subsequent line counted as native. It reported 17%
    where the real figure is 4%.
  - Defaulting --since to the most recent tag diffs a release against
    itself at tag time and reports zero changes. It now skips the
    version being released.

RELEASE_PROCESS.md documents the command and the rule that a release
whose notes exit non-zero is not tagged.

feat(lang): title, metrics, datasource, input, output and to are contextual

Six words stop being reserved. They are field names inside model, report
and render syntax, and reserving them globally meant a program could not
call a variable `title` or a function `to_json`. This came up three times
while writing the compiler in its own language — `model` in Phase 4,
`metrics` and `title` again while building layout rendering — which is a
reliable signal that users would hit it constantly.

The parsers now match them by spelling in the one position where they can
only mean one thing: `input:`/`output:` inside a model, `title:`,
`datasource:` and `metrics:` inside a report, `to` inside a render. A
misspelling there is still a parse error naming the expected word.

Done in both implementations at once, so the lexer differential — which
compares token streams and would have caught exactly this kind of skew —
stayed green throughout. `title` now lexes as IDENT in both.

Four conformance tests cover it: the words used as variables and function
names, and model and report blocks still parsing. Reserved words that
genuinely need to be reserved are untouched.

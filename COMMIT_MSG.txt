feat(ml): inference runtime for model/predict; fix UTF-8 column counting

`predict` was emitting a call to strata_predict, which was defined
nowhere — any program that used the feature failed to link. It now runs:

  model RiskScorer { input: tensor[float,1,3]; output: tensor[float,1,2]; }
  tensor[float,1,2] scores = predict RiskScorer(features);   -> 6.5, 7.25

One dense layer, output = input x W + b, with weights read from a
whitespace-separated text file. No hidden layers, no activations beyond
the identity, no training, no accelerator, no framework interop. An
untrained model predicts zeros rather than garbage. The README says all
of that rather than letting "native ML" stand.

That is enough for the E006 contract to mean something end to end: a
tensor of the wrong shape stops the build naming both shapes, and the
value that would have been silently wrong is never computed.

A bare model name is now the model itself, so Strata code never has to
name the generated C global — `strata_model_load(RiskScorer, path)`
rather than `&RiskScorer_instance`. The model struct aliases the runtime
type so strata_predict reads it without depending on field order.

Prelude return types are registered for code generation. Without them
str(strata_tensor_get(t, 0)) could not tell a float from an int and
truncated 6.5 to 6 — the same class of bug as the foreign return types
last change, now fixed at the source with a table rather than one call
site at a time.

The wasm prelude gets the same dense layer. Weight loading is absent
there: a freestanding module has no file system, so a host must write
weights into memory.

Separately, the lexer differential caught a real defect the moment a
source file contained an em-dash: the Strata lexer counted columns in
bytes while the oracle counts characters, so one multi-byte character in
a comment shifted every diagnostic column on that line. UTF-8
continuation bytes no longer advance the column.

Conformance 89; all ten suites green; fixpoint holds.

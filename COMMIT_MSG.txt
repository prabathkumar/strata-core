feat(deploy): the image is built and run, and the service logs

I said the image could not be built here because there is no Docker on the
development machine. The cloud side of this session has Docker; I should have
checked before saying otherwise. It has no route to any container registry,
so the two-stage Dockerfile — which pulls debian:bookworm-slim — is still
CI-only, but the half that needs no registry can be proven here and now is.

deploy/build_scratch_image.sh compiles the service, collects exactly what ldd
reports, builds a FROM scratch image, runs it and asks for a page. 5.35 MB;
/login renders, a sign-in and an order both work through the container.

Running it found what reading it could not: docker logs was empty. A C
program whose stdout is a pipe gets a 4KB block buffer, so the line the
service prints at startup sat in libc and would have stayed there until the
process exited — a running service that looks dead to anyone watching. The
runtime preamble line-buffers stdout and unbuffers stderr from before main,
and journey_survive.py asserts the startup line reaches a pipe.

docs: the ten stages, and what closing one requires

STAGES.md records the end-to-end pipeline a program passes through — write,
check, repair, format, build, test, run, survive, deploy, operate — which are
closed and which suite proves each. Eight are closed; repair and deploy are
partly closed; operate has barely started.

The definition matters more than the table: a stage is closed when a suite
that runs on every commit proves it and exits non-zero when it does not. Not
when the code exists, and not when it worked once by hand. Anything never run
is marked never run rather than counted — the LLM repair backend and the
Debian image are both in that state.

Closing a stage now means three things together: the suite is in CI, the row
here says so and names it, and Prabath is told. He asked to hear about every
stage closed.

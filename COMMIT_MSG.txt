feat(layout): cross-tier contract — a renamed column fails the build at the UI

The argument for Strata being a language rather than a library, working
end to end. A column declared in a database block, queried in the middle
tier and rendered in a layout is resolved at build time, so:

  [E004] Field 'service_name' not in 'ServiceMetric' (line 38, col 26)
  Hint: Valid fields: ['id', 'svc_name', ...]

points at the line of UI that used it. Not a runtime 500 in front of a
user. The for-in loop variable carries the row type from the query to the
screen, which is the part a library cannot do.

Layouts parse and type check in both implementations; all eight suites
stay green and the fixpoint still holds. They do not render yet — that is
marked in the roadmap rather than implied.

Element tags are contextual, not reserved. Rather than fixing a tag list
— which would make every new widget a compiler change — an identifier in
statement position is an element unless it is being assigned, accessed,
called or queried. `row`, `text` and `chart_bar` all work, and a variable
may still be called `row` outside a layout.

Three ambiguities had to be settled:

  - `[` after an element label opens a property list, not an index. The
    postfix chain added in Phase 1 swallowed it, so `canvas view
    [width = 500]` parsed the props as a subscript. The guard is checked
    both at the top of the postfix loop and inside its index branch,
    because a member access consumed earlier in the same iteration
    otherwise falls straight through — `text Row.service_name [...]`.
  - A bare identifier after a tag names the element rather than referring
    to a value, so `canvas topology_view` is not an undefined variable.
    It is inferred as an expression only when it actually resolves.
  - A bare function name is a reference, not a call: an event handler
    passed as `[action = on_click]`. Reports and layouts are now checked
    after functions are registered, since a handler may be declared
    further down the file.

examples/cross_tier_contract.sta is the demo, and six conformance tests
cover the rules including the rename. examples/ now compiles 9 of 16, up
from 7: both dashboards build.

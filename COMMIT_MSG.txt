fix: track compiler/runtime_preamble.c; verify the committed tree builds

Every CI step failed on b7cc628 while every suite passed locally. The
cause was not any of them: .gitignore carried `*.c` to exclude generated
output, and compiler/runtime_preamble.c — extracted in the codegen work
as the single source of the C runtime prelude — matched that pattern and
was never committed. The compiler reads it on every run, so a clone had
no prelude and nothing could build.

.gitignore now excludes generated C but keeps the prelude, which is
source rather than output.

The real fix is the guard. test_suite/clean_checkout.py exports HEAD with
`git archive` — exactly what a clone gets — and runs the conformance
suite inside it. A file the build needs but does not track now fails one
named step instead of turning every step red at once with no indication
of why. It runs first in CI, before the suites it would otherwise
invalidate.

This is the third variant of the same failure in this project: a check
that cannot be run the way it actually runs. The YAML-indented Python
that made the stdlib appear unparseable, the gcc-versus-clang divergence
on implicit declarations, and now a working tree that contains a file the
repository does not.
